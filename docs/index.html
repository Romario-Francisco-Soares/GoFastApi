Framework HTTP para Go

GoFastAPI.

Uma experiência de desenvolvimento inspirada no FastAPI, construída sobre net/http. Rotas expressivas, contexto, middleware, DI e OpenAPI — com interoperabilidade com o ecossistema Go.

Estado do projeto. GoFastAPI é uma biblioteca Go completa para construção de APIs HTTP, com paridade funcional com FastAPI e servidor de produção inspirado em Uvicorn — tudo em um único binário Go autocontido.
net/httpBase HTTP nativa do Go
TrieRotas dinâmicas indexadas por segmento
3 scopesSingleton, Request e Transient
WorkersSupervisor multiprocesso nativo
TLS/mTLSCertificados e clientes autenticados
Hot ReloadRecarga automática em desenvolvimento

Visão geral

GoFastAPI procura remover boilerplate sem esconder o modelo de execução do Go. A aplicação pode ser utilizada como framework ou integrada em um servidor existente por meio de app.Handler(), que retorna um http.Handler.

Experiência de alto nível

Registro declarativo de rotas, respostas, dependências, grupos e metadados OpenAPI.

Interoperabilidade

Handlers e middleware continuam compatíveis com interfaces padrão da biblioteca HTTP do Go.

Eficiência consciente

Context lazy e handlers idiomáticos sem reflexão no hot path. Handlers genéricos tipados usam reflexão em execução.

Operação integrada

Servidor, TLS/mTLS, graceful shutdown, health checks e supervisor multiprocesso com limites conhecidos.

Quick start

Adicione o módulo ao seu projeto:

go get github.com/Romario-Francisco-Soares/GoFastApi@latest
package main

import (
    "log"
    gofast "github.com/Romario-Francisco-Soares/GoFastApi"
)

func main() {
    app := gofast.New(
        gofast.Title("Minha API"),
        gofast.Version("1.0.0"),
        gofast.Description("API de produção em Go, sem boilerplate"),
    )

    // Middleware de produção em uma linha
    app.Use(gofast.Recovery(nil))                    // panic → 500, sem expor stack
    app.Use(gofast.RequestID(""))                    // X-Request-ID para rastreamento
    app.Use(gofast.CORS(gofast.CORSConfig{           // CORS com preflight
        AllowOrigins: []string{"*"},
        AllowMethods: []string{"GET", "POST", "PUT", "DELETE", "OPTIONS"},
    }))
    app.Use(gofast.Compression())                    // gzip automático
    app.Use(gofast.Timeout(10 * time.Second))        // timeout por requisição

    // Rotas com agrupamento (prefixo, tags, dependências compartilhadas)
    usuarios := app.Group("/usuarios", gofast.GroupTags("usuarios"))
    usuarios.GET("/{id}", func(ctx *gofast.Context) (any, error) {
        return gofast.OK(map[string]string{"id": ctx.Param("id")}), nil
    })
    usuarios.POST("/", func(ctx *gofast.Context) (any, error) {
        return gofast.Created(map[string]string{"status": "criado"}), nil
    })

    // Método HTTP arbitrário
    app.Route("PROPFIND", "/arquivos/{id}", func(ctx *gofast.Context) (any, error) {
        return gofast.OK(map[string]string{"method": "PROPFIND"}), nil
    })

    // DI com escopos: Singleton, Request, Transient
    app.Provide(novoBanco, gofast.Singleton())

    // Background tasks executadas após o flush da resposta
    app.POST("/emails", func(ctx *gofast.Context) (any, error) {
        ctx.BackgroundTasks().Add(func() {
            // envia e-mail após a resposta ir para o cliente
        })
        return gofast.OK(map[string]bool{"aceito": true}), nil
    })

    cfg := gofast.DefaultServerConfig()
    cfg.Addr = ":8000"
    cfg.Workers = 4          // supervisor multiprocesso nativo
    cfg.GracefulTimeout = 30 * time.Second

    log.Fatal(app.Run(cfg))
}

Execute o exemplo no repositório com go run ./cmd/server. Por padrão a aplicação registra:

/docsInterface Swagger UI.

Rotas e grupos

App aceita GET, POST, PUT, PATCH, DELETE, OPTIONS, HEAD, TRACE, WebSocket e Route() para métodos HTTP arbitrários. O sub-router oferece Group() com prefixo, tags e dependências compartilhadas, e AddRoute.

router := gofast.NewRouter()
users := router.Group("/users", gofast.GroupTags("users"))

users.GET("/{id}", func(ctx *gofast.Context) (any, error) {
    return gofast.OK(map[string]string{"id": ctx.Param("id")}), nil
})

app.Include(router, gofast.IncludeOption{Prefix: "/v1"})
app.Mount("/static", gofast.NewStaticFiles("./public"))
  • Rotas estáticas usam índice por método/caminho.
  • Rotas dinâmicas usam trie de segmentos para busca O(M) por segmento — sem varredura linear com regex.
  • {id} captura segmento único; {filepath:path} captura o restante (incluindo barras).
  • GET responde HEAD com o corpo suprimido.
  • 405/Allow é gerado quando caminho existe, mas o método não.
  • Middlewares por rota são pré-compilados no registro, não reconstruídos por requisição.

type CreateItem struct {
    Name string `json:"name"`
}

func (p *CreateItem) Validate() error {
    if strings.TrimSpace(p.Name) == "" {
        return errors.New("name is required")
    }
    return nil
}

app.POST("/items", func(ctx *gofast.Context, input CreateItem) (any, error) {
    return gofast.Created(map[string]string{"name": input.Name}), nil
})

O binding tipado suporta um corpo JSON por handler com struct/map/slice/interface conforme a assinatura compilada e permite Validate() error. Assinaturas genéricas fazem reflect.Call em cada requisição. Binding manual permanece disponível pelos helpers do Context.

Não é Pydantic: tags arbitrárias, aliases, defaults e binding automático integral de header/cookie/form/file ainda não estão implementados.

Injeção de dependências

Cada aplicação possui seu próprio container DI (não global).

type UserService struct{}
func NewUserService() *UserService { return &UserService{} }

app.Provide(NewUserService, gofast.Singleton())

app.GET("/me", func(ctx *gofast.Context, svc *UserService) (any, error) {
    return gofast.OK(map[string]string{"state": "ready"}), nil
}, gofast.RouteOption{
    Dependencies: []gofast.Depends{{Dependency: (*UserService)(nil)}},
})
EscopoSemântica
Singleton()Uma instância por container/processo, inicialização lazy sincronizada com sync.Once.
Request()Uma instância por contexto/requisição (armazenada em ctx.state).
Transient()Nova instância por resolução.

Providers podem retornar T, (T, error), (T, func()) ou (T, func() error). Dependências cíclicas são detectadas. Cleanups request/transient são executados ao fim da requisição e cleanups singleton no fechamento da aplicação. Overrides devem ocorrer durante o startup/configuração.

Sessões e segurança

Cookie de sessão AES-GCM

app.Use(gofast.SessionMiddleware(gofast.SessionConfig{
    Secret:   os.Getenv("SESSION_SECRET"),
    CookieName: "session",
    HTTPOnly: true,
    Secure: true,
    SameSite: http.SameSiteLaxMode,
}))

A sessão é stateless e armazenada em cookie autenticado/cifrado AES-GCM, limitada em tamanho. Use segredo aleatório e de alta entropia, fora do repositório. Em produção HTTPS, configure Secure/HTTPOnly/SameSite conforme seu modelo de ameaça.

Autenticação

O pacote raiz fornece APIKey (header/query/cookie), HTTPBearer, HTTPBasic e OAuth2Bearer com callbacks de validação. Os dados do usuário autenticado ficam em ctx.Principal().

app.Use(gofast.APIKey(gofast.APIKeyConfig{
    Name:  "X-API-Key",
    In:    gofast.APIKeyHeader,
    Secret: "super-secret-key",
}))

app.Use(gofast.HTTPBearer(gofast.BearerConfig{
    Secret: "test-token",
}))

app.Use(gofast.HTTPBasic(gofast.BasicConfig{
    Username: "user",
    Password: "pass",
}))

Validação de tokens é delegada a um provedor/callback externo. Não há servidor OAuth2, emissão de JWT, refresh tokens ou autenticação OIDC completa.

OpenAPI e documentação

app.OpenAPI() gera um objeto OpenAPI 3.1 básico. Use RouteOption para informar tags, summary, description, operation ID, responses, deprecated e security. Registre schemes com app.AddSecurityScheme.

Rotas internas: /openapi.json, /docs e /redoc.

app.AddSecurityScheme("BearerAuth", gofast.SecurityScheme{
    Type:             "http",
    Scheme:           "bearer",
    BearerFormat:     "JWT",
    Description:      "Autenticação via Bearer token JWT",
})

app.AddSecurityScheme("ApiKey", gofast.APIKeyScheme("X-API-Key", gofast.APIKeyHeader, "API Key no header"))
Schema limitado: a biblioteca ainda não infere completamente request/response schemas dos tipos Go. ResponseModel não gera JSON Schema automaticamente; callbacks, webhooks e exemplos automáticos não estão implementados.

WebSocket e streaming

WebSocket oferece handshake/upgrade e frames básicos de texto, binário, JSON, ping/pong, close, limites e deadlines. Não há fragmentação completa, subprotocolos, extensões de compressão nem política de Origin configurável integrada.

app.GET("/ws", func(ctx *gofast.Context, conn gofast.WebSocketConn) error {
    for {
        msg, err := conn.ReadJSON()
        if err != nil {
            return err
        }
        if err := conn.WriteJSON(msg); err != nil {
            return err
        }
    }
})

SSE e streaming genérico são fornecidos por SSE, SSEWithHeartbeat, WriteEvent, Stream e StreamWithContentType. Em deploy, ajuste os timeouts do servidor e do reverse proxy para conexões longas.

Background tasks

app.POST("/emails", func(ctx *gofast.Context) (any, error) {
    ctx.BackgroundTasks().Add(func() {
        // tarefa curta após o flush da resposta
    })
    return gofast.OK(map[string]bool{"queued": true}), nil
})

As tarefas são em processo, executadas sequencialmente após o flush da resposta no ciclo de atendimento. Erros/panics são logados. Não existe persistência, retry durável ou distribuição; utilize uma fila externa para tarefas críticas.

Health checks

app.Health().RegisterChecker("database", func() error {
    return db.PingContext(context.Background())
})

// Marque readiness conforme o lifecycle da aplicação.
app.OnStart(func(ctx context.Context) error {
    app.Health().SetReady(true)
    return nil
})

/health/live verifica liveness; /health/ready consulta readiness e checkers registrados. Checkers externos devem ser rápidos e aplicar seus próprios timeouts.

Servidor e configuração

cfg := gofast.DefaultServerConfig()
cfg.Addr = ":8000"
cfg.ReadHeaderTimeout = 5 * time.Second
cfg.IdleTimeout = 75 * time.Second
cfg.GracefulTimeout = 30 * time.Second
cfg.Workers = 1

if err := app.Run(cfg); err != nil {
    log.Fatal(err)
}

Single-process usa net/http.Server, bloqueia até shutdown/erro, suporta TCP/UDS/FD, TLS e mTLS, timeouts HTTP, keep-alive, limites, proxy headers e trusted hosts. App.Serve(ctx, listener) permite listener externo e cancelamento por contexto.

Workers e Supervisor

Com Workers > 1, o Supervisor inicia processos filhos, herda o listener por file descriptor e usa um pipe de prontidão (FD) antes de considerar o worker iniciado. Oferece restart policy, backoff, limite de reinicializações, PID file, limite de requests e shutdown controlado.

O health monitor verifica se o processo ainda existe (sinal 0). Não há heartbeat periódico nem detecção de processo vivo porém travado. O modo é multiprocesso; não é pool de goroutines. Cada worker termina TLS independentemente quando TLS está configurado.

CLI integrada

O CLI é executado dentro da aplicação que já foi construída por meio de app.RunCLI(os.Args[1:]) ou gofast.RunCLI(app, args). Ele não é um carregador genérico de projetos a partir de um caminho de arquivo.

Configuração

O pacote config fornece carregamento de configuração com precedência explícita:

  1. Defaults — valores padrão do ServerConfig.
  2. Arquivo — JSON com campos explicitamente definidos.
  3. Variáveis de ambiente — prefixo GOFAST_ (ex: GOFAST_ADDR, GOFAST_WORKERS).
  4. CLI — overrides da linha de comando (última prioridade).
import "github.com/Romario-Francisco-Soares/GoFastApi/config"

cfg := config.MustLoad(
    config.WithEnvPrefix("GOFAST_"),
    config.WithConfigFile("config.json"),
    config.WithCLIOverrides(map[string]any{"Workers": 4}),
)
app.Run(*cfg)

Variáveis de ambiente são mapeadas por reflection nos campos de ServerConfig (strings, inteiros, booleanos, floats e slices de string). Campos não definidos via env mantêm o valor do nível anterior na precedência.

Hot Reload

O pacote hotreload fornece recarga automática do servidor quando arquivos .go são modificados. Útil para desenvolvimento (modo dev):

import "github.com/Romario-Francisco-Soares/GoFastApi/hotreload"

reloader := hotreload.NewHotReloader(app, []string{"."}, 1*time.Second)
reloader.Start()
defer reloader.Stop()

Quando cfg.Reload = true é definido no ServerConfig, o App.Run() inicia automaticamente o hot reloader, que monitora arquivos .go nos diretórios configurados, recompila o pacote main com go build e inicia um novo processo com o binário atualizado. Se a compilação falhar, o servidor atual continua atendendo.

Performance comparativa: Go vs GoFastAPI vs FastAPI

Uma comparação da capacidade de processamento, latência e memória das três implementações em um endpoint HTTP equivalente. O objetivo é mostrar o custo da camada de abstração da GoFastAPI em relação ao Go nativo e contextualizar sua vantagem de execução frente ao FastAPI Python.

Nota metodológica: os valores de desempenho apresentados nesta seção são referentes a uma rodada de testes executada em ambiente de desenvolvimento específico (Linux/AMD64, contêiner com 2 vCPUs efetivas e 4 GiB de RAM). Os números refletem as condições daquela execução e não constituem garantia de desempenho em produção, pois carga real, tamanho do payload, middlewares, DI, TLS, banco de dados, workers, hardware e configuração de rede alteram os resultados.
